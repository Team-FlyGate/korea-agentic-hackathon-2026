# OpenFold3 실행과 pLDDT 실측

2026-09-27 측정. NVIDIA 스킬 `msa-structure-prediction-pipeline` 을 설치해 그 문서가 적은
규격대로 호출했다. 구조 예측을 파이프라인에 붙일 수 있는지 확인하고, 신뢰도 지표가 입력
조건에 얼마나 좌우되는지를 우리 손으로 재는 것이 목적이었다.

## 무엇을 돌렸나

PARP1 촉매도메인(PDB 4R6E) 사슬 A, 358 잔기다. 지금 도킹 케이스가 쓰는 그 단백질이다.
같은 서열을 같은 모델에 두 번 넣었고 **바꾼 것은 MSA 하나뿐이다.**

```bash
set -a; source .env; set +a
.venv/bin/python scripts/openfold3_smoke.py --no-msa          # 정렬 없이 질의 서열만
.venv/bin/python scripts/openfold3_smoke.py --label with-msa  # 문서대로 MSA-Search 먼저
```

## 결과

| 조건 | pLDDT | confidence | pTM | 걸린 시간 |
|---|---|---|---|---|
| 질의 서열만 (히트 0건) | **31.89** | 0.123 | 0.123 | 5.3초 |
| Uniref30 정렬 203줄 | **90.08** | 0.737 | 0.737 | MSA 19.9초 + 예측 21.4초 |

같은 단백질, 같은 모델, 같은 날이다. **pLDDT 가 31.9에서 90.1로 바뀐다.**
원자 2,824줄짜리 PDB 가 양쪽 모두 나왔고 파일은 `eval/results/openfold3_4R6E_A_1.pdb` 다.
결과 JSON 은 `eval/results/openfold3_smoke_{no-msa,with-msa}.json` 에 있다.

## 이 수치가 받치는 것

과잉해석 규칙 17번(구조 예측 신뢰도 지표 해석 제한)의 근거가 도구 문서 인용에서
**우리 실측으로 올라간다.** 스킬 문서는 "A larger, higher-quality MSA typically yields higher
pLDDT" 라고만 적었는데, 그 차이가 이 단백질에서 58점이라는 것을 우리가 쟀다.

그래서 이렇게 말할 수 있다. pLDDT 는 **모델이 자기 예측에 매긴 신뢰도**이고 입력 정렬의
깊이에 따라 세 배 가까이 움직인다. 결합 세기나 실험 구조와의 일치도로 옮기면 안 되고,
서로 다른 조건에서 나온 값을 견주어 순위를 매기면 더욱 안 된다.

## 규격에서 걸린 것

**MSA 필드를 비우면 422 가 난다.** 응답이 이유를 정확히 알려 준다.

> "Each protein sequence in the input must be accompanied by a non-empty MSA or paired_msa.
> If the user intent is to provide 0 hits for this protein sequence, then an MSA consisting of
> only the query sequence should be provided"

그래서 `--no-msa` 는 정렬을 빼는 것이 아니라 **질의 서열만 담은 a3m 을 넣는 경로**다.
스크립트가 그렇게 만든다.

**MSA-Search 응답의 데이터베이스 키가 요청한 이름과 다르게 온다.** 요청에
`Uniref30_2302` 를 넣었고 응답 키도 `Uniref30_2302` 였는데, 문서 예제는 `uniref30` 으로
받는다. 예제를 그대로 베끼면 `KeyError` 가 난다. 스크립트는 받은 키 가운데 a3m 이 있는
첫 번째를 쓰고 무엇을 썼는지 결과에 남긴다.

## 아직 하지 않은 것

- **리간드를 넣은 복합체 예측.** 팀원 C가 단백질과 니라파립으로 ipTM 0.66 과 리간드 RMSD
  1.16 Å 을 받았다고 공유했으나, 설치한 스킬 문서에는 리간드 분자 형식이 없다. 팀원 C에게
  요청 본문을 받아 재현한다
- **예측 구조와 실험 구조의 RMSD.** 우리가 직접 재지 않았다. 재려면 4R6E 실험 구조를 받아
  정렬해야 한다
- **NAT 도구 등록.** 지금은 스크립트로만 부른다. 도구로 등록하면 작성자 에이전트가 직접
  부르고 근거 ID(`fold:openfold3:<id>`)가 주장에 붙는다
