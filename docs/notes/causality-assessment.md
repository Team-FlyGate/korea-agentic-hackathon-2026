# 인과성 평가 기준과 우리 파이프라인의 접점

2026-09-27 작성. 팀원 B가 회의에서 화면으로 공유한 평가 도구 원본과 국내 약물감시 흐름
설명서를 받아 정리했다. 원본 파일은 저장소에 두지 않고 로컬에 보관한다.

회의에서 "인과성 평가 알고리즘을 시스템 로직에 그대로 반영한다"고 정했으므로, 무엇을
반영하는지 여기서 확정한다. 회의록에 "배점 원본 대조가 필요하다"고 남긴 것도 이 문서로 해소한다.

## 1. 국내에서 실제로 쓰는 도구 셋

원본에 실린 것이 셋이고 성격이 다르다. **등급 이름이 서로 달라 섞어 쓰면 안 된다.**

### WHO-UMC 기준 (서술형 6등급)

확실함, 상당히 확실함, 가능함, 가능성 적음, 평가 곤란, 평가 불가로 나뉜다. 판정은 네 가지를
본다. 투여와 발현의 시간 관계가 타당한가, 다른 약이나 동반 질환으로 설명되는가, 투여를
중단했을 때 합당한 반응을 보이는가, 재투여에서 결정적인가.

재투여 정보가 없으면 확실함이 아니라 상당히 확실함까지만 간다. 공식 보고서식에 이 6등급이
실려 있다.

### 한국형 인과성 평가 알고리즘 ver 2.0 (점수형)

여덟 항목의 점수를 더한다. 최고 19점, 최저 -13점이다.

| 항목 | 배점 |
|---|---|
| 시간적 선후관계 | 합당 +3, 모순 -3, 정보 없음 0 |
| 감량 또는 중단 | 중단 후 호전 +3, 무관한 경과 -2, 시행 안 함 0, 정보 없음 0 |
| 이상사례의 과거력 | 예 +1, 아니오 -1, 정보 없음 0 |
| 병용약물 | 단독 설명 불가 +2, 단독 설명 가능 -3, 상호작용으로 설명 +2, 설명 없음 0 |
| 비약물요인 | 설명되지 않음 +1, 설명됨 -1, 정보 없음 0 |
| 약물에 대해 알려진 정보 | 허가사항에 반영 +3, 증례보고만 있음 +2, 알려진 바 없음 0 |
| 재투약 | 재발함 +3, 재발하지 않음 -2, 재투약 안 함 0, 정보 없음 0 |
| 특이적인 검사 | 양성 +3, 음성 -1, 결과 미상 0, 정보 없음 0 |

구간은 12점 이상 확실함, 6~11점 가능성 높음, 2~5점 가능성 있음, 1점 이하 가능성 낮음이다.

**회의에서 들린 "+3, -3, 0"은 이 표의 시간적 선후관계 배점이다.** 회의록의 확인 항목을 이것으로
닫는다. 등급 이름은 WHO-UMC와 달리 네 단계이고 "상당히 확실함"이 없다.

### Naranjo Scale (점수형, 원본 대조 필요)

공유받은 자료의 Naranjo 표는 열 항목을 모두 "예 +1, 아니오 0, 모르거나 수행 안 됨 0"으로
적고 총점 구간을 9점 이상 definite, 5~8 probable, 1~4 possible, 0 doubtful로 둔다.

**이 배점은 원 논문(Naranjo 등 1981)과 다르다.** 원 척도는 항목마다 가중치가 다르고 음수 배점이
있다. 자료에 실린 대로 구현하면 원 척도를 구현한 것이 아니므로, **Naranjo를 쓸 경우 원 논문
배점으로 다시 대조해야 한다.** 대조하기 전에는 시스템에 넣지 않는다.

## 2. 국내 흐름 안에서 인과성 평가가 일어나는 지점

보고자가 서식에 적어 보내면 지역의약품안전센터 28곳의 평가자가 **개별 사례마다** 인과성을
매기고, 그 평가가 붙은 보고가 한국의약품안전관리원(KIDS)의 KAERS 데이터베이스에 쌓인다.
KIDS는 쌓인 보고에서 통계적 불균형 지표와 사람 검토로 실마리정보를 찾아 식약처에 제공하고,
식약처가 허가사항 변경 명령이나 안전성 서한으로 조치한다.

우리 도구와 직접 맞닿는 대목이 둘이다.

**첫째, KIDS의 신호 탐지가 우리가 쓰는 지표와 같은 계열이다.** 국내 연구에서 PRR과 ROR 2 이상,
카이제곱 4 이상, 보고 3건 이상, IC 신뢰구간 하한 0 초과 같은 기준을 쓴다. KIDS 내부의 공식
임계값은 공개 자료에서 확인하지 못했다. 우리 `prr_calculator` 오라클이 실제 규제 절차의 선별
단계와 같은 지표를 다룬다고 말할 수 있고, 그 이상은 주장하지 않는다.

**둘째, 라벨 추가가 인과 확정이 아니라는 근거를 규제기관 문서에서 얻었다.** 국내 시판 후 사례로
허가사항에 문구를 추가할 때 "다만, 이로써 곧 해당성분과 다음의 이상사례 간에 인과관계가
입증된 것을 의미하는 것은 아니다"라는 단서가 함께 붙는다. 규칙 14번(라벨 기재와 인과 구분)의
근거가 도구 문서에서 규제기관 문서로 한 단계 올라간다.

## 2-1. 보고 서식과 제출 창구

팀원 B가 실제 서식 셋을 링크로 공유했다. 회의에서 팀원 A가 "보고서 문서 예시가 있으면
좋겠다" 고 한 것에 대한 답이고, 우리 산출물이 결국 보고서 형태라 형식을 맞출 근거가 된다.

| 누가 쓰는 서식 | 무엇 | 주소 |
|---|---|---|
| 병원 | 제출된 이상사례 보고 사례와 담당자가 정리한 해설 | `dept.snuh.org/dept/DMC/bbs/bbsView.do?menuId=008042&cid=14082` |
| 일반인 | 의약품안전나라의 온라인 보고 서식 | `nedrug.mfds.go.kr/CCCBA03F010/getReport` |
| 약사 | 약사가 쓰는 보고 형식을 설명한 기사 | `kpanews.co.kr/news/articleView.html?idxno=542594` |

공식 서식은 식약처 공고 제2023-057호 「의약품등 이상사례·약물이상반응 보고서식」이고
의약전문가용과 일반인용 두 가지가 있다. 의약전문가용은 환자정보, 이상사례정보, 의약품정보,
보고자정보, 보고서정보, 종합의견 여섯 묶음으로 나뉜다.

**약국과 의료기관은 중대한 이상사례만 보고 의무가 있다**(약사법 제68조의8 제2항). 그 밖의
보고는 자율이고, 국내 보고의 상당수가 자율 보고와 지역센터 활동에서 나온다.

## 2-2. 서식을 우리 산출물에 어떻게 잇는가

**지금은 잇지 않았다.** 서식을 자료로 기록했을 뿐이고, 우리 케이스 브리프는 도킹에서 사람
근거까지의 흐름을 따라 쓰여 있어 보고 서식과 구조가 다르다. 그대로 두면 현장에서 쓰는 문서와
우리 산출물이 만나지 않는다.

이어 붙일 자리는 분명하다. 서식의 여섯 묶음 가운데 셋은 우리가 이미 근거로 들고 있고, 둘은
공개 데이터에 없으며, 하나는 우리 크리틱이 검사할 대상이다.

| 서식 항목 | 우리 쪽에 있는 것 | 상태 |
|---|---|---|
| 가. 환자정보 | 없음. FAERS 공개본의 나이군과 성별뿐 | 개별 사례를 다룰 때만 채워진다 |
| 나. 이상사례정보 | 반응명, 결과, 중대 여부. `faers:2x2:<drug>-<event>` | 있음 |
| 다. 의약품정보 | 의심약물 구분, 투약 조치, 중단 후 호전, 재투여 | 있음. 한국형 알고리즘 항목과 그대로 대응한다 |
| 라. 보고자정보 | 보고자 자격 | FAERS 에 있으나 우리가 쓰지 않는다 |
| 마. 보고서정보 | 보고 유형, 최초인지 추가인지 | 쓰지 않는다 |
| 바. 종합의견 | **모델이 쓰는 요약** | **크리틱이 검사할 대상** |

**바 항목이 우리 주제와 정확히 겹친다.** 종합의견은 사람이 사례를 읽고 쓰는 서술이고, 실무자
인터뷰에서 "내러티브의 완성도가 이후 모든 보고서의 품질을 좌우한다" 고 한 그 문서다. 우리가
검사하려는 것이 바로 그 서술이 근거를 넘어섰는지다.

**마감 뒤에 할 것.** 케이스 브리프에 서식 여섯 묶음을 표제로 두고, 채울 수 없는 항목은 비운
채로 무엇이 없는지 적는다. 지금 브리프가 쓰는 "단계별 근거" 구성을 버리지 않고 그 아래에
서식 대응을 덧붙이는 쪽이 안전하다. 제출 전에 구조를 바꾸면 수치 검사와 그림이 함께 흔들린다.

## 3. 정답 데이터를 어디서 얻는가

공유받은 조사로 **인과성 평가 결과와 경과 서술을 함께 공개하는 데이터가 없다**는 것이 분명해졌다.

| 데이터 | 인과성 평가 결과 | 경과 서술 | 접근 |
|---|---|---|---|
| FAERS (openFDA) | 없음 | 없음 | 즉시 |
| EudraVigilance 공개본 | 없음 (원자료에는 항목 있음) | 없음 | 즉시 |
| VAERS, MAUDE | 없음 | **있음** | 즉시 |
| KAERS 원시자료 | **있음** (보고자의 WHO-UMC 평가) | 미확인 | 신청 후 한 달 이상 |
| 증례 보고 논문 | 일부에 저자 평가 있음 | 있음 | 즉시 |

여기서 세 가지가 따라온다.

**FAERS를 "정답"이라 부르지 않는다.** 회의에서 FAERS 판정을 정답으로 두고 적중률을 보자고
했으나, 공개본에는 인과성 평가 필드가 없다. 대신 쓸 수 있는 것은 구조화된 필드다.
`drugcharacterization`(의심, 병용, 상호작용), `actiondrug`(중단, 감량 등), `drugadditional`
(중단 후 호전), `drugrecurreadministration`(재투여 시 재발), `reactionoutcome`(결과)이
한국형 알고리즘의 항목과 그대로 대응한다. **즉 FAERS 필드로 알고리즘 점수의 일부를 기계적으로
채울 수 있고, 사람 판정과 맞는지는 별도로 확인해야 한다.**

**필드 보유율이 생각보다 낮다.** 니라파립과 혈소판감소증 보고 1,065건에서 투약 시작일이 있는
것이 828건, 중단 후 호전 여부가 예 또는 아니오인 것이 700건, 재투여 필드가 있는 것이 168건이다.
게다가 openFDA 검색은 조건이 같은 약물에 걸렸는지 보장하지 않아 이 숫자는 상한이다.
재투약 항목은 대부분 0점으로 들어간다고 보아야 한다.

**경과 서술이 필요하면 VAERS나 MAUDE, 또는 증례 보고 논문을 쓴다.** 팀원 B의 제안대로 FAERS
구조화 필드에서 경과 서술을 생성해 쓰는 방법도 있으나, 그 경우 생성한 서술이 근거를 넘어서지
않는지가 바로 우리 크리틱이 검사할 대상이 된다. 생성물을 정답으로 쓰지 않도록 갈라 둔다.

## 4. 시스템에 넣을 것과 넣지 않을 것

| 무엇 | 어떻게 |
|---|---|
| 한국형 알고리즘 ver 2.0 여덟 항목과 배점 | 점수 계산은 파이썬으로. 크리틱 2단 숫자 오라클과 같은 성격이다 |
| WHO-UMC 6등급 | 등급 이름을 라벨로 쓸 때만. 한국형 네 단계와 섞지 않는다 |
| Naranjo | 원 논문 배점으로 대조한 뒤에 넣는다. 지금은 넣지 않는다 |
| 점수에서 등급으로 가는 구간 | 고정 규칙. 모델에 맡기지 않는다 |
| 항목별 선택지 판단 | 사례 텍스트를 읽어야 하므로 모델이 제안하고 근거 문장을 함께 남긴다 |
| 인과성 판정 자체를 최종 결론으로 발표 | 하지 않는다. 지역센터 평가자의 일이다 |

마지막 줄이 우리 주장의 경계다. 알고리즘을 채점해 주는 것과 인과성을 판정하는 것은 다르고,
후자를 했다고 적으면 우리 크리틱이 반려할 주장이 된다.
