# FlyGate 저장소 읽는 법

FlyGate는 약물 안전성 에이전트입니다. 하는 일은 하나입니다.
**모델이 쓴 문장이 그 문장이 기댄 자료를 넘어섰는지 검사합니다.**

저장소는 <https://github.com/Team-FlyGate/Project-FlyGate>, 데모는 <https://flygate.kr>입니다.
파일이 300개가 넘어 어디부터 볼지 막막하기에 주제별로 나눠 적습니다.

## 한눈에

명령 하나를 돌려 보면 무엇을 하는지 바로 보입니다.

```bash
flygate grade NIRAPARIB thrombocytopenia
```

```json
{
  "grade": "B",
  "evidence_ids": [
    "grade:NIRAPARIB:thrombocytopenia@2026Q2",
    "faers:2x2:NIRAPARIB:thrombocytopenia@2026Q2",
    "label:b7f675e2-159c-490c-b6f4-3f16d9492b7d#warnings_and_cautions",
    "pubmed:29767688#rct",
    "pubmed:40687421#case_report"
  ]
}
```

**모든 답에 근거 ID가 붙습니다.** 등급이 B인 이유가 FAERS 2x2 표 하나, 라벨의 어느 절,
논문 몇 편인지 전부 되짚을 수 있습니다. 이 저장소는 이 한 줄을 만들려고 쓰였습니다.

## 저장소 구성

| 폴더 | 무엇이 있나 | 규모 |
|---|---|---|
| `api/_fv/` | 판단 로직 전부 | 파이썬 3,400줄 |
| `pipeline/` | 데이터를 만드는 쪽 | 4,800줄 |
| `agent/` | `flygate` CLI, 스킬, 샌드박스 정책 | 2,000줄 |
| `web/` | 대시보드 | 8,000줄 |
| `skills/` | NVIDIA Agent Skills 규격 11개 | 36개 파일 |
| `tests/` | pytest | 147개 |

처음이면 `docs/ARCHITECTURE.md`와 `api/_fv/triage.py` 둘만 봐도 얼개가 잡힙니다.

## 1. 데이터

FAERS는 FDA가 분기마다 zip으로 내놓는 부작용 보고입니다. 2026년 2분기 한 분기에 42만 건입니다.

그대로 쓰면 안 됩니다. 같은 사건이 여러 번 보고되고, 약 이름이 제각각입니다.

`pipeline/faers/`가 DuckDB 위에 다섯 계층을 쌓습니다.

```
raw_*    분기 zip 그대로. 분기마다 다른 컬럼명(gndr_cod → sex)을 맞춘다
core_*   중복 제거, 약물명 정규화, 중대성 플래그
ref_*    상품명 → 성분명 대응표
sig_*    2x2 표와 불균형 지표
ops_*    사람 검토 대기열
```

세 가지만 기억하면 됩니다.

**중복 제거에 규칙이 있습니다.** 한 사건(caseid)에 보고 버전(primaryid)이 쌓입니다.
caseid마다 최신 버전 하나만 남기고 FDA 삭제 목록을 뺍니다. 안 하면 건수가 부풀려집니다.

**약물명 정규화가 큽니다.** 원문 62만 종이 48만 종이 됩니다.
`METFORMIN HYDROCHLORIDE`를 `METFORMIN`으로 묶는 일입니다.

**지표는 SQL이 계산합니다.** PRR, ROR, 카이제곱, IC 하한까지 전부 쿼리입니다.
모델은 숫자에 손대지 못합니다. 모델이 숫자를 만들면 검증할 길이 없어집니다.

## 2. 판단: 두 모델을 나눠 쓰기

42만 건을 큰 모델로 다 읽으면 느리고 비쌉니다. 규칙 하나로 거르면 중대한 사례를 놓칩니다.

그래서 둘로 나눴습니다.

| 단계 | 모델 | 하는 일 | 속도 |
|---|---|---|---|
| 반사 | Jev | 7문항 확률 | 296ms |
| 숙고 | Nemotron 3 Super 120B | 근거 ID 붙여 메모 작성 | 수 초 |

**판단과 글쓰기는 다른 일입니다.** "사람이 먼저 봐야 하나"는 확률 하나면 됩니다.
"왜 그런가"는 문장이 필요합니다. 한 모델에 맡기면 싼 일에 비싼 값을 치릅니다.

그 앞에 규칙이 있습니다. ICH 최소 4요소, 결과 코드, 약물 역할은 코드가 봅니다.
**규칙으로 되는 일을 모델에 묻는 것은 비용이면서 새로운 오류입니다.**

## 3. Jev를 어디에 넣었나

Jev는 글을 쓰지 않습니다. 사실을 JSON으로 주고 질문을 던지면 값만 돌려줍니다.

실제로 보내는 질문입니다. `api/_fv/triage.py`에 있습니다.

```json
{
  "serious": {
    "type": "noul",
    "instructions": "Does this case meet ICH E2A seriousness criteria (death, life-threatening, hospitalization, disability, congenital anomaly, or other medically important event)?"
  },
  "causality": {
    "type": "choice",
    "instructions": "WHO-UMC causality category for NIRAPARIB and the principal reaction, based only on this report.",
    "criteria": {
      "certain": "certain", "probable": "probable / likely", "possible": "possible",
      "unlikely": "unlikely", "unassessable": "unassessable / unclassifiable"
    }
  },
  "route": {
    "type": "choice",
    "instructions": "What should the safety system do next with this case?",
    "criteria": {
      "close": "no safety concern beyond known profile; archive",
      "monitor": "keep in routine aggregate surveillance",
      "signal_review": "potential new signal; needs signal assessment",
      "expedite": "serious and unexpected; prepare expedited report and human review now"
    }
  }
}
```

일곱 문항을 **한 호출에 같이 넣습니다.** state를 한 번 읽고 함께 평가하므로 일곱 번
부르는 것보다 싸고 빠릅니다.

**질문을 규제 용어로 쪼갠 것이 요령입니다.** "이 사례가 심각한가"로 물으면 답이 흔들립니다.
"ICH E2A 기준에 해당하는가"로 물으면 기준이 박혀서 답이 안정됩니다.

### 재 보다가 알게 된 것

처음엔 Jev가 잘 가르는 줄 알았습니다. 니라파립 열 건을 넣었더니 이렇게 나왔습니다.

| 판정기 | 사람이 봐야 한다 | 지연 |
|---|---|---|
| 고정 규칙 | 10 / 10 | 0.01ms |
| Nemotron 3 Super | 10 / 10 | 824ms |
| **Jev** | **4 / 10** | 255ms |

여섯 건을 걸러 냈으니 좋아 보였습니다.

그래서 **약물명과 반응명을 가려 봤습니다.** `DRUG_A`, `REACTION_1`로 바꿨습니다.

Jev도 10건을 전부 올렸습니다.

걸러 낸 근거가 통계가 아니라 **약 이름에서 온 사전 지식**이었습니다.
"오심, 피로, 혈소판감소는 항암제에 흔하다"를 이미 알고 있던 겁니다.

이 발견이 설계를 바꿨습니다.

- **질문을 다시 썼습니다.** "사람이 봐야 하나" 대신 "라벨에 아직 없는 새 신호인가"로
- **근거를 state에 직접 넣었습니다.** 라벨 기재 여부를 넣자 확률이 0.04와 0.87로 갈렸습니다
- **이름을 가린 조건을 본 측정으로 삼았습니다.** FAERS 440건에서 AUROC 0.940, 정확도 0.830.
  다수 클래스로 찍는 기준선이 0.568이니 실제로 가릅니다

### 말하지 않기로 한 것

같은 34건에서 Jev가 Nemotron보다 AUROC가 높았습니다. 0.972 대 0.863입니다.

그래도 "Jev가 더 정확하다"고 쓰지 않았습니다. **n이 34라 그 차이를 통계로 가를 수 없고**,
Nemotron 쪽은 40건 중 6건이 타임아웃으로 빠졌습니다.

대신 이렇게 적었습니다. "NVIDIA 스킬 위에 구성한 워크플로에 비자기회귀 판단 모델을 병용해
속도와 유의한 개선을 얻었다."

같은 내용인데 넘지 않는 문장입니다. 넘는 문장을 잡는 프로젝트가 발표문에서 넘으면
앞뒤가 안 맞습니다.

### 한계

- **보정이 안 맞습니다.** ECE 0.128. 0.4~0.6 구간에서 예측 0.485에 실제 0.702입니다.
  임계값을 그대로 쓰면 중대 사례를 놓칩니다
- **글을 못 씁니다.** 논문 요약이나 상충 결과 조정은 Nemotron이 합니다
- **입력 토큰이 오히려 많습니다.** 질문 정의까지 입력에 들어갑니다. 929 대 309.
  비용 이점은 입력 단가가 낮고 출력이 무료인 데서 옵니다

## 4. 근거 ID와 크리틱 3단

이 프로젝트의 중심입니다.

주장마다 ID가 붙습니다.

```
faers:case:183331543
faers:2x2:NIRAPARIB:thrombocytopenia@2026Q2
label:b7f675e2-...#warnings_and_cautions
pubmed:29767688#rct
```

검사는 세 단계입니다.

| 단계 | 보는 것 | 모델 |
|---|---|---|
| T1 | 인용한 ID가 실재하는가 | 안 씀 |
| T2 | 문장 속 숫자가 원본과 맞는가 (±1.1%) | 안 씀 |
| T3 | 근거가 허락하는 범위를 넘었는가 | 씀 |

**앞의 둘이 모델을 안 쓰는 게 핵심입니다.** 없는 근거를 지어내거나 숫자를 바꾸는 것은
문자열 대조와 숫자 비교로 잡힙니다.

모델은 마지막 하나에만 씁니다. 이런 문장입니다.

> "니라파립의 Vina 점수가 PARP1에서 가장 낮으므로 PARP1 선택성이 있다."

숫자가 맞고 근거 ID도 제대로 붙었습니다. 그런데 서로 다른 단백질의 점수를 견준 것이라
도구 문서가 금지한 추론입니다. T1도 T2도 못 잡습니다.

**규칙은 직접 짓지 않았습니다.** 도구와 데이터 제공자가 문서에 적어 둔 금지 문장을
옮겼습니다. 예를 들어 NVIDIA는 DiffDock 문서에 이렇게 적었습니다.

> Do not convert confidence directly into binding affinity.

만든 쪽이 스스로 금지한 추론이라 취향 다툼이 되지 않습니다.

## 5. 시판 전: BioNeMo NIM 네 종

```
MSA-Search      닮은 서열을 모아 줄을 맞춘다
   ↓
OpenFold3       그 정렬에서 단백질 구조를 예측한다
```

`bionemo-msa-structure-prediction-pipeline`을 따릅니다.

PARP1으로 재 본 값입니다. 구조 CA RMSD 1.0 Å, 재도킹 0.71 Å, 친화도 순위 상관 0.767.

## 6. 커넥톰: 초파리를 쓴 이유

이름의 Fly가 여기서 옵니다. MaleCNS는 초파리 중추신경계 커넥톰입니다.
뉴런 약 16만 6천 개, CC-BY 4.0입니다.

쓰는 것은 중앙뇌 부분그래프입니다. 뉴런 49,244개, 연결 1,051,255개.

**정직하게 말하면 비유입니다.** 초파리 뇌가 감각 신호를 전부 처리하지 않고 걸러 내듯,
보고를 전부 큰 모델에 넣지 않고 앞단에서 거릅니다.

초파리 회로를 모사한 모델을 돌리는 것이 아닙니다. 커넥톰은 화면에서 구조를 보여 주고,
실제 걸러내기는 규칙과 Jev가 합니다. 이 구분을 흐리면 우리가 막으려는 바로 그 과장이 됩니다.

## 7. 껍데기: CLI, 샌드박스, 스킬

**CLI.** `./scripts/install_flygate.sh` 한 줄로 설치됩니다.
명령 아홉 개가 모두 근거 ID 붙은 JSON을 냅니다.

```
login  chat  triage  grade  signals  kr-causality  critic  discover  watch
```

`flygate`만 치면 대화형이 열립니다. 자연어 요청을 받아 실행할 명령을 제안하고
**확인을 받은 뒤** 돌립니다.

```
$ flygate grade niraparib thrombocytopenia
이 명령은 외부 API를 사용하거나 로컬 파일을 만들 수 있습니다.
실행할까요? [y/N]
```

**샌드박스.** OpenShell 정책은 `agent/policy/flygate.yaml`입니다.
나가는 연결을 기본으로 막고 목록에 적은 곳만 엽니다. 루트 권한 없이 돕니다.
**보고서를 밖으로 보내는 경로는 아예 열지 않았습니다.** 판정과 제출은 사람이 합니다.

**스킬.** 우리 기능 열한 개를 공식 `SKILL.md` 규격으로 포장했습니다.

## 8. 무엇을 어떻게 쟀나

| 물은 것 | 결과 | 데이터 |
|---|---|---|
| 중대 사례를 놓치지 않으면서 사람 일을 줄이는가 | 247/250 탐지, 업무량 302 → 138건 | FAERS 440건 |
| 빠른가 | 7문항 296ms (자기회귀 2,286ms) | 같은 사례 27건 |
| 공인된 연관을 알아보는가 | AUC 0.960(OMOP), 0.983(EU-ADR) | 참조 세트 480쌍 |
| 라벨이 바뀌기 전에 알 수 있었는가 | 57건 중 21건, 오경보 70건 중 1건 | 구형 AERS 2004~2012 |
| 과잉해석을 막는가 | 틀린 주장 31/31 반려, 정상 6/6 통과 | 평가 문장 50건 |

**숫자보다 조건이 중요합니다.**

중대 사례를 잴 때 **결과 코드를 가렸습니다.** 결과 코드가 입력에 있으면 "중대한가"를
맞히기가 너무 쉬워집니다. 정답도 같은 코드로 정하기 때문입니다. 가리지 않으면 거의 저절로
참이 되는 수치가 나옵니다.

라벨 변경 예측은 **시점을 못 박았습니다.** 2013년 이전 보고만 씁니다.
조치일 이후 데이터를 쓰면 답을 미리 본 셈입니다.

팀의 약사가 이런 함정을 열다섯 개 짚어 주었고 `docs/PHARMACIST_REVIEW.md`에 반영 내역이
있습니다.

# 직접 만들려면

## 준비물

| 무엇 | 어디서 | 비용 |
|---|---|---|
| NVIDIA 키 (`nvapi-`) | build.nvidia.com | 무료. 레이트리밋으로 관리 |
| TypeSafe 키 | 콘솔 가입 | 크레딧을 넣어야 키가 나옴. 최소 5달러 |
| FAERS | FDA 분기별 zip | 무료. 55개 분기에 고유 사례 1,760만 건 |
| 허가 라벨 | openFDA `drug/label.json` | 무료, 키 불필요 |
| 문헌 | PubMed E-utilities | 무료. 초당 3회 제한 |
| 참조 세트 | OMOP, EU-ADR, 시간 색인 | 무료 |

런타임 의존성은 `fastapi`와 `httpx` 둘입니다. 여기에 DuckDB를 더하면 끝입니다.
모델 호출이 전부 HTTP라 무거운 프레임워크가 필요 없습니다.

## 순서

### 1단계. 게이트 확인 (반나절)

코드를 쓰기 전에 막힐 곳부터 봅니다.

```bash
curl -s https://integrate.api.nvidia.com/v1/models \
  -H "Authorization: Bearer $NVIDIA_API_KEY" | head
```

생물학 NIM은 계정에 Public API Endpoints 권한이 있어야 합니다. 없으면 호출이 전부
에러로 돌아옵니다. DiffDock에 최소 한 번 POST를 보내 200이 오는지 확인하세요.

**여기서 막히면 뒤가 전부 무너집니다.** 권한 요청은 답이 며칠 걸립니다.

### 2단계. 데이터 창고 구축 (하루)

1. 원천 적재. 분기마다 컬럼명이 다르니 정규화 표를 먼저
2. 중복 제거. caseid마다 최신 버전 하나, FDA 삭제 목록 제외
3. 약물명 정규화. 유효성분 우선
4. 2x2 표와 지표. 전부 SQL로

**여기까지만 와도 모델 없이 쓸 만한 게 나옵니다.** 약 하나 넣고 상위 반응을 뽑아 보면
데이터가 제대로 들어갔는지 바로 압니다.

### 3단계. 판단 층 구성 (하루)

규칙으로 되는 것과 모델이 필요한 것을 먼저 가릅니다.

```
규칙   최소 요소, 결과 코드, 약물 역할, 지정 의학적 사건 목록
모델   중대성, 예측성, 인과 가능성
```

**규칙을 먼저 통과시키고 남은 것만 모델에 넘기세요.** 반대로 하면 비용이 몇 배가 되고
모델이 틀릴 기회만 늘어납니다.

### 4단계. 근거 ID와 검사 (하루)

주장마다 ID를 붙이게 하고, ID가 실재하는지와 숫자가 맞는지를 **모델 없이** 검사합니다.

가장 값어치 있는 부분인데 만들기는 제일 쉽습니다. 문자열 대조와 숫자 비교가 전부입니다.

### 5단계. 측정 (하루)

만든 다음이 아니라 만들면서 잽니다. 셋만 지키면 됩니다.

- **정답을 입력에서 빼기.** 결과 코드로 정답을 정하면서 그 코드를 입력에 넣으면 잰 게 아닙니다
- **기준선 함께 내기.** 다수 클래스로 찍은 정확도를 옆에 적으세요. 없으면 0.83이 좋은 건지 모릅니다
- **시점 고정하기.** "미리 알 수 있었는가"는 그 시점 이전 데이터만 씁니다

## 부딪히게 되는 것들

실제로 겪은 것만 적습니다.

**DiffDock 인자 이름이 문서마다 다릅니다.** 블루프린트는 `num_steps`, 공식 예제는 `steps`.
422가 오면 바꿔 보세요. SMILES를 넣을 때 `ligand_file_type`은 `"smiles"`가 아니라 `"txt"`입니다.

**OpenFold3는 MSA가 없으면 422입니다.** 맞은 서열이 0건이어도 필드는 있어야 합니다.

**Jev는 질문 형마다 `criteria` 모양이 다릅니다.** `choice`는 보기 맵, `score`는 순서 있는
목록입니다. 빠뜨리면 422입니다.

**라벨 단서를 절 전체에서 찾으면 안 됩니다.** 허가사항 경고 절은 반응 하나씩 담은 번호
소항목의 목록입니다.

이소트레티노인 라벨에서 이런 일이 있었습니다.

```
5.8  Hearing Impairment   ... causality for this reaction have not been established
5.10 Inflammatory Bowel Disease   (그런 문구 없음)
```

절 전체를 훑었더니 5.8의 문구가 5.10에도, 5.3 우울에도 붙었습니다.
**등급이 그 쌍이 아니라 그 약에 대해 말하고 있었습니다.** 반응이 언급된 소항목 안에서만
찾게 고치니 C가 B로 올라갔습니다.

**미국 라벨의 상투 문구를 단서로 읽지 마세요.** 이상반응 절은 거의 모두 "자발 보고라
빈도를 추정하거나 인과를 확정할 수 없다"로 시작합니다. 일반 안내이지 판정이 아닙니다.

**PRR이 크다고 근거가 단단한 게 아닙니다.** 이소트레티노인과 염증성장질환은 PRR 495로
압도적입니다. 그런데 2003~2011년 보고 2,214건 중 87.8퍼센트가 변호사 보고였습니다.
같은 기간 FAERS 전체는 3.6퍼센트입니다. 소송이 만든 숫자입니다.

**openFDA 성분명 필드는 현행 허가 라벨이 있어야 채워집니다.** 시장에서 사라진 약은 보고가
수만 건 있어도 0으로 나옵니다.

| 조회 필드 | 바이옥스 |
|---|---|
| `openfda.generic_name` | 0건 |
| `medicinalproduct` (보고자 원문) | **44,279건** |

0이 부재의 증거가 아니라 조회 방식의 산물인 경우입니다.

## 정리

관통하는 생각은 하나입니다. **모델이 만든 문장을 무엇과 대조해 믿을지 먼저 정한다.**

사람 판정끼리도 잘 안 맞아 정답으로 삼기 어렵습니다. 형식 검사로는 숫자와 출처가 맞는데
결론만 넘어선 주장을 못 거릅니다.

그래서 도구와 데이터 제공자가 문서에 적어 둔 금지 문장을 기준으로 삼았습니다.
취향이 아니라 만든 쪽이 밝힌 한계라서, 기계가 검사할 수 있고 사람이 다투지 않습니다.

저장소를 여실 분은 `docs/EVALUATION.md`부터 보시기를 권합니다.
무엇을 어떤 조건에서 쟀는지가 거기 다 있습니다.
