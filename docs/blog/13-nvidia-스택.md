# NVIDIA 에이전트 스택 실전

[시리즈 색인](00-시리즈-색인.md) · 앞 편은 [비유인가 기여인가](12-커넥톰-대조.md)입니다.

여기까지가 판단 로직이었습니다. 이 편은 그것을 **에이전트로 포장하고 가둬 두는** 쪽입니다.

## Agent Skills: 382개 중에서 고르기

NVIDIA가 공개한 스킬 카탈로그에 폴더가 **382개** 있습니다. 스킬은 `SKILL.md` 하나에 무엇을
하는 도구인지, 어떻게 부르는지, 무엇을 하면 안 되는지를 적은 규격입니다.

카탈로그가 크니 다 보면 안 됩니다. 필요한 것을 이름으로 찾는 쪽이 빠릅니다.
실제로 쓴 것만 적으면 넷입니다.

| 스킬 | 어디에 |
|---|---|
| `diffdock-nim` | 도킹 호출 규격. **과잉해석 규칙 하나의 출처가 이 문서** |
| `bionemo-msa-structure-prediction-pipeline` | MSA에서 구조까지 이어 붙이는 순서 |
| `bionemo-openfold2-nim` | 구조 예측 규칙 2종의 출처 |
| `nemotron-policy-generator` | 안전 정책 생성 |

스킬 문서를 규칙의 출처로 쓴 것이 여기서 배운 방식입니다. 스킬은 도구 사용법만 적은 것이
아니고 하면 안 되는 것도 적혀 있습니다. 그 문장을 크리틱 규칙으로 옮기면 취향 다툼이
되지 않습니다. [8편](08-근거-id-크리틱.md)과 [10편](10-bionemo-네-단계.md)에서 본 것이 이것입니다.

우리 기능 **열한 개**도 같은 규격으로 포장했습니다. 트리아지, 근거 등급, 문헌 읽기, 크리틱,
창고 조회 같은 것들입니다. 같은 규격으로 쓰면 다른 에이전트가 우리 것을 가져다 씁니다.

## CLI 하나로 사람과 에이전트가 같은 명령을 씁니다

`flygate` CLI입니다. 설치는 한 줄입니다.

```bash
./scripts/install_flygate.sh
```

명령 아홉 개입니다.

```
login  chat  triage  grade  signals  kr-causality  critic  discover  watch
```

전부 근거 ID가 붙은 JSON을 냅니다. 화면에 보기 좋은 표를 내는 것이 아니고 기계가 받을 수
있는 형태를 냅니다. 사람이 볼 표는 그 JSON에서 만듭니다.

이 설계가 왜 좋은가 하면, **에이전트와 사람이 같은 도구를 쓰기 때문**입니다. 에이전트가 하는
일을 사람이 그대로 재현할 수 있고, 사람이 의심스러우면 같은 명령을 직접 쳐 볼 수 있습니다.
에이전트 전용 경로를 따로 두면 그 경로에서 일어난 일을 사람이 확인하기 어렵습니다.

인자 없이 `flygate`만 치면 대화형 모드가 열립니다. 자연어 요청을 받아 **실행할 명령을 제안한
뒤 확인을 받고** 돌립니다. 바로 실행하지 않는 것이 중요합니다. 자연어 해석이 틀릴 수 있고,
틀린 명령이 실행되기 전에 사람이 봅니다.

## OpenShell 샌드박스: 나가는 길을 먼저 막습니다

NemoClaw 배포 구성 안에서 OpenClaw 에이전트가 같은 CLI를 씁니다. 정책은
`agent/policy/flygate.yaml`입니다.

원칙이 하나입니다. 나가는 연결을 기본으로 모두 막고 목록에 적은 호스트만 엽니다.
차단 목록을 만드는 방식이 아니고 허용 목록을 만드는 방식입니다. 차단 목록은 빠뜨리면
열리고, 허용 목록은 빠뜨리면 막힙니다. 틀렸을 때 안전한 쪽으로 틀립니다.

파일 접근은 Landlock으로 제한합니다. 커널 수준에서 막으므로 프로세스가 우회할 수 없습니다.
루트 권한 없이 돕니다.

보고서를 밖으로 보내는 경로는 아예 열지 않았습니다. 사람이 판정하고 사람이 제출한다는
뜻입니다. 에이전트가 규제기관에 무언가를 보낼 수 있으면 그건 다른 종류의 시스템입니다.

## 정책이 실제로 강제되는지 확인했습니다

정책 파일을 쓰는 것과 그 정책이 강제되는 것은 다릅니다. 스모크 테스트를 돌려
`pass=9 fail=0`을 받았습니다.

| 구분 | 대상 | 결과 |
|---|---|---|
| 허용 | `api.fda.gov` | `http=200` |
| 허용 | `dailymed.nlm.nih.gov` | `http=200` |
| 허용 | `eutils.ncbi.nlm.nih.gov` | `http=200` |
| 허용 | `integrate.api.nvidia.com` | `http=200` |
| **차단** | `example.com` | `CONNECT tunnel failed, response 403` |
| **차단** | `github.com` | `CONNECT tunnel failed, response 403` |
| 쓰기 거부 | `/etc` | `Permission denied` |
| 쓰기 허용 | `/work/out` | 쓰고 읽고 삭제까지 성공 |
| 쓰기 거부 | `/sandbox` | `Permission denied` |

`integrate.api.nvidia.com`이 401이 아니라 200을 돌려준 것이 중요합니다. 프록시가 진짜
키를 끼워 넣었다는 뜻입니다.

샌드박스 안에서 `printenv NVIDIA_API_KEY`를 하면 값이 아니라 자리표시자가 나옵니다.

```
openshell:resolve:env:v3_NVIDIA_API_KEY
```

에이전트가 키를 볼 수 없는데 호출은 됩니다. 프록시가 나가는 요청에 진짜 키를 끼웁니다.
에이전트가 키를 어딘가에 적어 보내는 사고를 구조로 막습니다.

## 로그를 읽을 때 걸린 것

네트워크 거부는 게이트웨이 로그에 남습니다.

```
NET:OPEN [MED] DENIED /usr/bin/curl(189) -> example.com:443
  [reason:endpoint example.com:443 is not allowed by any policy]
```

그런데 파일시스템 거부는 DENIED로 남지 않습니다. Landlock이 커널에서 EPERM으로 끊기
때문에 게이트웨이가 볼 이벤트가 없습니다.

이걸 모르면 "파일 정책이 안 걸렸다"고 오해합니다. 대신 적용 기록이 남습니다.

```
Applying Landlock filesystem sandbox [abi:V2 compat:BestEffort ro:12 rw:3]
Landlock ruleset built [rules_applied:14 skipped:1]
```

`skipped:1`은 이미지에 없는 경로 하나입니다. 읽기 전용 목록에 적었는데 이미지에 만들지
않았습니다. 호환 모드가 `best_effort`라 건너뛰고 넘어갑니다.

**`skipped`가 0인지 확인하세요.** 넘어간 규칙이 있는데 넘어갔다는 것을 모르면 정책이 적용된
줄 알게 됩니다. 반드시 걸려야 하는 경로면 `hard_requirement`로 바꿉니다.
